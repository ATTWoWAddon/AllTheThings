# Deprecated WoW API calls in ATT

Audit date: October 14, 2026

ATT contains **18 distinct deprecated function names used outside `app.WOWAPI`**: nine in shared addon paths that still select the old interface, five behind checks that prefer the replacement API, and four in version-specific paths or generated data callbacks. This includes five functions belonging to the deprecated `UIDropDownMenu` framework. Original Parser sources and their generated copies count as the same API, not separate findings.

## Scope and source versions

- ATT baseline: [`a9ceed3bf928764cb322fdc70f8e49976c4b01f5`](https://github.com/ATTWoWAddon/AllTheThings/commit/a9ceed3bf928764cb322fdc70f8e49976c4b01f5). ATT source links below are pinned to this commit.
- Scan scope: 3,987 tracked Lua files, 43 XML files, and the addon TOC, including hidden `.contrib` sources and tracked generated `db` files.
- Current Blizzard source: Gethe [`12.1.5 / 70391`](https://github.com/Gethe/wow-ui-source/commit/18c6d677b605b312f3d813d498404631fb941977).
- Historical Blizzard snapshots: [`11.0.0`](https://github.com/Gethe/wow-ui-source/commit/742bf9604e0009bebb9a61a4f953d2661f8b387e), [`11.0.5`](https://github.com/Gethe/wow-ui-source/commit/fa3531505e3e2406f9e3d5a0fbd9644bd5c85227), and [`12.1.0`](https://github.com/Gethe/wow-ui-source/commit/a89e9d0ceb7f6cd31e8fc5ca7df1a338ac0b1b58), covering compatibility functions subsequently removed from the current source.
- Deprecation criteria: explicit Blizzard deprecated definitions or comments, or a Warcraft Wiki deprecation statement. A legacy global name or a Lua language-server diagnostic alone does not establish deprecation.

The scope excludes fallback definitions inside `src/WoW API Wrappers.lua`, callers whose local aliases resolve to `app.WOWAPI`, comments, and injected test mocks. Parser strings that become runtime callbacks are included. Callers were traced through local aliases, API availability checks, numeric build conditions, and Parser conditions.

This is a static audit. It establishes the call sites and source deprecation status; it does not establish an in-game failure on every client listed in the addon TOC. Retail removal dates and older Classic client behaviour must be evaluated separately.

## Housing return fields relying on compatibility

`C_HousingCatalog.GetCatalogEntryInfo` and `C_HousingCatalog.CreateCatalogSearcher` remain current API names. Their appearance in a deprecated bridge is not sufficient to count them as deprecated functions.

ATT nevertheless depends on the old result shape in [src/Classes/Decor.lua:41](https://github.com/ATTWoWAddon/AllTheThings/blob/a9ceed3bf928764cb322fdc70f8e49976c4b01f5/src/Classes/Decor.lua#L41) and at lines [83](https://github.com/ATTWoWAddon/AllTheThings/blob/a9ceed3bf928764cb322fdc70f8e49976c4b01f5/src/Classes/Decor.lua#L83), [129](https://github.com/ATTWoWAddon/AllTheThings/blob/a9ceed3bf928764cb322fdc70f8e49976c4b01f5/src/Classes/Decor.lua#L129), and [151](https://github.com/ATTWoWAddon/AllTheThings/blob/a9ceed3bf928764cb322fdc70f8e49976c4b01f5/src/Classes/Decor.lua#L151). The current [housing compatibility bridge](https://github.com/Gethe/wow-ui-source/blob/18c6d677b605b312f3d813d498404631fb941977/Interface/AddOns/Blizzard_Deprecated/Mainline/Deprecated_12_0_5.lua#L73) supplies these fields:

| Old field used by ATT | Current field or structure supplied by the bridge |
| --- | --- |
| `quantity` | `totalNumStored` |
| `numPlaced` | `totalNumPlaced` |
| `entryID` | A constructed ID table containing `recordID`, `entryType`, and compatibility fields. |

The bridge only runs when `loadDeprecationFallbacks` is enabled. The field accesses therefore need a separate migration to the current catalog result shape. This finding is additional to the 18 deprecated function names.

## Excluded legacy references and diagnostics

- Item, currency, spell, and specialization calls whose local aliases already resolve to `app.WOWAPI` are outside this audit's bypass scope.
- `GetNumSpecializations`, `GetSpecializationInfoByID`, `GetAddOnMemoryUsage`, and `UpdateAddOnMemoryUsage` remain normal API definitions in the audited Blizzard source and were not counted solely because they are globals.
- `GetCurrencyListInfo`, `GetQuestLogRewardSpell`, `GetQuestLogRewardCurrencyInfo`, and several old quest helpers occur in compatibility paths, but a removed Retail API without an explicit deprecation statement was not counted under this audit's criteria.
- `math.atan2` is a Lua library diagnostic, not a WoW API finding. Diagnostic comments around `C_Transmog.GetSlotForInventoryType` and `C_TransmogSets.GetAllSourceIDs` did not establish deprecation.
- `C_AreaPoiInfo.GetAreaPOIInfo`, `C_VignetteInfo.GetVignetteInfo`, `C_ChatInfo.RegisterAddonMessagePrefix`, and `C_ChatInfo.SendAddonMessage` retain their function names. Historical compatibility adjustments to result fields or return types do not make those current names deprecated.

## Follow up work

1. Route the direct shared callers through existing wrappers where available, and define compatibility handling for the other replacements.
2. Rebuild the sound-pack dropdown using the new menu framework while preserving support for client branches that need the legacy menu.
3. Update the Parser callback sources for aura, Phoenix mount, and combat-log checks, then regenerate the affected databases. Validate API availability against each affected client branch.
4. Migrate housing field access to the current catalog structure and verify the result with deprecation fallbacks disabled.

The five existing replacement-first callers can be consolidated into `app.WOWAPI` independently of those behavioural migrations.
