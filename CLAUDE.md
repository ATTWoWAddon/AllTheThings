# CLAUDE.md

@AGENTS.md

The contribution rules in `AGENTS.md` (imported above) always apply: commit subject format, the `Assisted-by:` trailer, PR sections, and source evidence for every data change. This file adds the conventions for working on the database itself.

## Repository layout

- `src/`: addon Lua. `db/`: the compiled databases, generated by the Parser. Never edit them by hand; change the source DB and rebuild.
- `.contrib/.db/`: the source DB.
  - `standard/`: retail and the Classic flavours. `forever/`: WoW Forever. `shared/`: loaded by every build (race constants, headers, header IDs).
  - `build - <flavour>.bat` runs the Parser for one flavour (`build - forever.bat`, `build - retail.bat`, ...); `debug - ...` variants exist too.
- `.contrib/src/Parser/`: the Parser's C# source. `.tools/Parser.exe` is the compiled copy that the build scripts run (Windows, .NET Framework, native `lua54.dll`). Changes to the Parser source only take effect after `Parser.exe` is rebuilt.
- After a rebuild, check that the diff in `db/` matches the source change before committing it.

## Working with data

- Sources: in-game observation, Contributor Reports, or Wowhead (see `AGENTS.md`). When a value isn't known yet (quest giver, coordinate, creature ID), leave a `-- TODO:` comment. Never guess.
- Don't remove data just because Wowhead no longer shows it. Unseen data is often hidden on Wowhead until someone interacts with it, so keep it until its absence is confirmed in game.
- Every `sourceQuest`/`sourceQuests` must point at a quest defined in the DB, or the Parser errors ("Referenced Source Quest ... has not been Sourced").
- Every encounter `e(id, ...)` needs a `creatureID` (or `crs`); one without crashes the addon. Comment out an encounter whose creature isn't known yet (`--e(3403),\t-- Overseer Wrex`) with a TODO.
- Keep CRLF line endings in files that use them, and keep comments that sit inside data tables.

### Formatting

- Bare table keys (`creatureID =`, not `["creatureID"] =`).
- Empty elements collapse to `i(123),\t-- Name`.
- Only write `groups = { ... }` when the element has other fields too; otherwise pass the children directly: `i(262888, { i(264049), ... })`.
- No space between leading tabs and a function call. Keep the right-aligned padding of short IDs in `crs` lists.
- Creature comments include the NPC's title when it has one: `qg = 253139,\t-- Gorhak <Magram Clan Quartermaster>` (for `qg`, `cr`, `crs` and `n()`).
- Never write `lvl = 1`; omit `lvl`. Battleground brackets use `lvl = { min, max }`.
- No coordinates inside instances. Don't repeat `maps` on a child when the parent already lists that map.
- Hints players need ("on the table next to Archmage Arugal") go in a `description`, not a comment. Don't restate what the in-game tooltip already shows. Prefer `learnedAt` + `requireSkill` over descriptions of skill levels (descriptions are expensive).

### Quests

- `n(QUESTS)` lists are sorted by quest name, case-insensitive and natural (5 before 10, (9/17) before (10/17)). Same-named quests keep their chain order, and nested quests move with their parent.
- A quest goes in the zone file where its giver stands (class quests too). Dungeon quests go in the instance file's `n(QUESTS)`. Quests shared by both factions with different givers use `aqd`/`hqd`.
- Item-started quests: `qs = <itemID>,\t-- Name (QS!)` with no `qg`; list the item where it drops or is sold. Object-started quests: `provider = { "o", id }` plus coords.
- Provided quest items: `qi = <itemID>,\t-- Name (PQI!)`, right after the giver line. They don't count toward objective numbering.
- Objectives:
  - Never reference hidden credit NPCs (Wowhead's "Credit" / "[DNT] Kill Credit: ..."). Drop the reference but keep any provided item.
  - `cr`/`crs` only on objectives that involve a real creature: kill targets, item droppers, "Deliver X to / Speak with <NPC>" (with that NPC's coord). Don't add a `cr` just to name the turn-in NPC.
  - Items looted from objects: `providers = { { "i", item }, { "o", object } }` plus the object's coords.
  - Comments carry the count: `-- 0/8 Tarnished Drudge slain`.
- Class quests use the class race constants (`ALLIANCE_SHAMANS`, `HORDE_PALADINS`, ...) instead of `ALLIANCE_ONLY`/`HORDE_ONLY` or hand-written race lists.
- Hidden quest triggers go under `root(ROOTS.HiddenQuestTriggers, { ... })` at the end of the related zone or instance file, with a comment or `description` saying what likely triggers them. `SpellEffect` rows with `Effect` 16 and `EffectMiscValue_0` = the quest ID show which spells complete a quest.

### Exploration

- Use `explorationHeader({ ... })`, sorted alphabetically. Add only areas that have a WorldMapOverlay.

## Timelines

- `timeline` is inherited: children without one take their parent's. It's always an array: `timeline = { ADDED_X }`, never `timeline = ADDED_X`.
- A nested element may carry only `REMOVED_*` when an ancestor has the matching `ADDED_*`. Don't copy the ancestor's `ADDED_*` down.
- **Never put a timeline on a shared (merged) header.** Headers declared by many files under the same parent merge into one object (continent/zone `m()`s, `n(QUESTS)`, `n(ACHIEVEMENTS)`, `n(BATTLEGROUNDS)`, `race()`, difficulty `d()`s), so one copy's timeline applies to everyone's content. Put it on the specific element underneath, e.g. on the zone, never the continent. A header with only one reference in its hierarchy should carry its own timeline. Check every copy of a header path before and after changing one.
- In `ROOTS.HiddenQuestTriggers`, generic headers (`expansion`, `cl`, `race`, `filter`, `d`, continent `m()`s, organizational `n()` constants) carry no timeline. Patch-specific headers (`inst()`, `header()`, `faction()`, `prof()`, feature `n()` constants, maps that came with a patch) may carry a base timeline, and then every HQT copy of that path must agree.
- `expansion(id, t)` discards any timeline set on itself; use `forcetimeline` or `expansionHeader(id, timeline, t)` to force one. Under `expansion()`, drop timelines equal to the expansion default (WOD 6.0.2/6.0.3, WRATH 3.0.2, CATA 4.0.3, LEGION 7.0.3, BFA 8.0.1, SL 9.0.2, DF 10.0.2, TWW 11.0.2, MID 12.0.1).
- Don't use `bubbleDown`/`bubbleDownSelf` for timelines; they override what nested timed elements pass down. Put the timeline on the element itself. A container item/object whose contents came with a patch carries that timeline itself.
- Before appending `{ timeline = ... }` to a call, check the constructor's signature (`ach(id, altID, t)` would read it as the wrong argument; arguments past `t` are ignored).
- `sharedData` errors ("No Source 't'") on an empty list, e.g. when every child is inside an `#if`.
- Zone files use `maproot(CONTINENT, ZONE, { ... })`; battleground files use `battleground(MAP, { ... })`.

## WoW Forever (`.contrib/.db/forever/`)

- Forever ships as 1.60.0 with no data beyond 1.80.0:
  - Strip content not available in that window and remove `SEASON_OF_DISCOVERY` blocks. Season of Discovery quests that Forever reuses are kept, but not their rune rewards.
  - Drop `ADDED_` < 1.60.1 and `REMOVED_`/`DELETED_` >= 1.80.0. Remove `#if AFTER x` (x >= 1.80) blocks, keeping `#else`; unwrap `#if BEFORE x` (x >= 1.80). Exceptions: keep `#if AFTER TBC` and `#if NOT OBJECTIVES`.
- New content uses `TIMELINE.ADDED_1_60_1`. Unconfirmed or not-yet-live content (e.g. a quest with no known giver) uses `TIMELINE.CREATED_1_60_1`, which hides it until a player reports it. A known starter (`qs` item, object `provider`, a header's `aqd`/`hqd`, or a previous quest that ends at the giver) counts as confirmed.
- New items added as rewards to quests that predate Forever get their own `timeline = { TIMELINE.ADDED_1_60_1 }`. Items on Forever-new quests are plain `i()`.
- Large systems (Craftsman's Writs, Waylaid Crates, Library Books) live in `expansion features/`, not in zone files. A header shared by several files is defined once, globally, under `.db/shared/lib/Headers/Forever/`, because `createHeader` errors on a duplicate.
- Check race/class availability against the client's `CharBaseInfo` (wago.tools), not Wowhead's quest race masks. Forever adds Undead Paladin, Dwarf Shaman, Gnome Priest, Human Hunter, Orc Mage, Troll Warlock, and the Skyborne races (`SKYBORNE_ALLIANCE` 95, `SKYBORNE_HORDE` 96). Class race constants live in `.config/constants/races.lua`.
- Achievements missing from the Forever client's Achievement DB2 are stripped.
- Exploration areas newly explorable in classic zones get `timeline = { TIMELINE.ADDED_1_60_1 }`.
